# Velocity independent audit

Subsequent fresh native execution is documented in [the full-bundle results](NATIVE-BUNDLE-RESULTS.md). This page preserves the earlier audit and its then-unexecuted proposal.

Audited locally on 2026-09-24. This document supplements the frozen Milestone 2.3–2.5 archive; it does not rewrite that archive. No Solana RPC request, native ELF execution, Clock modification, transaction submission, or new program experiment was performed for this audit.

The recorded Post-instruction results are internally consistent, and an independent finite solver reproduces the archived **4 / 4 / 4 / 3 conditional graph depths** in all six components. The evidence does **not** establish that whole observed transactions can safely run in parallel, that producer/consumer execution is invariant under reordering, or that the conditional model is implementable by changing transaction fee payers.

## What was checked

- Verified the frozen SHA-256 pins for the account snapshot, Linux execution record, runtime probe, and six full-block inputs. The materialized ELF is 6,050,397 bytes with SHA-256 `89d757b837724ab552d1ebf719245e33f9f93b722cb4331b5eec55202d94ca5c`.
- Independently reconstructed baseline and variant input data from the snapshot, five-instruction sysvar fixture, and timestamp mutations. All **78 recorded input account hashes** matched: six accounts in each of the baseline plus twelve cases.
- All 78 recorded output account metadata/hash records equal their corresponding input records; all recorded byte-difference lists and lamport/data-length deltas are empty/zero. This includes the **36 oracle records across twelve cases**, of which twelve belong to the four equality cases.
- Reanalyzed each cached full block and solved every connected component using the new bounded solver. Every result was exact within its search budget. Current maximum declared-lock depth is 4 in all six blocks; the deepest other component has depth **1, 2, 1, 2, 2, 1**, respectively, in the frozen plan's slot order.
- Solved each archived mixed constraint graph independently of its reported depth. All six have depths 4 / 4 / 4 / 3. The joint model keeps the two producer-to-consumer dependencies and three native market conflicts. Its witness places the producer before both consumers; the consumers may share a model layer.

The solver in `src/dependency-layers.ts` computes finite mathematical layers from explicit constraints. It supports at most twelve nodes and returns an inconclusive result with feasible upper bound when its search budget is exhausted. Eight focused tests passed, including comparison with independent assignment enumeration for 256 four-node conflict/precedence combinations. Strict TypeScript compilation passed. These checks prove properties of supplied graphs, not properties of a Solana runtime or an unobserved historical account prestate.

## Smallest useful reviewer inputs

Keep the review self-contained and name its evidence level. The following are separate review scopes, not a claim that a tiny graph fixture reproduces native execution.

1. **Conditional graph arithmetic:** a four-node fixture containing the three Anchor roles, native role, fifteen current conflict atoms, two producer-to-consumer dependencies, and explicit equality/payer hypotheses. Include the 4 / 4 / 4 / 3 ablations; deleting dependencies should yield 2 only as an explicitly invalid semantic comparison. Add a consumer conflict to return to 4; remove native constraints to obtain 2. A disconnected unchanged four-clique is a synthetic full-block masking control. Label every constructed control synthetic.
2. **Public block cross-check:** preserve one complete cached block, preferably slot 489572998 (289,262 bytes), with source path/hash, target signatures/indexes, account lock declarations, instruction bytes, and logs. Derive the target component and role evidence from those bytes. This supports one observed case only. For the six-block result, include all six originals; together they occupy 1,375,140 bytes. An actual program-buffer-upload block can provide a structural negative control in which no Velocity semantic refinement is authorized.
3. **Recorded Post-evidence check:** preserve the frozen M2.3 plan, raw Linux record (101,005 bytes), runtime probe (2,688 bytes), and the input bytes/metadata for the five real Post accounts plus serialized Instructions sysvar. Extracting this small account subset avoids requiring the full 8,095,780-byte snapshot just to compare Post input hashes. Include provenance back to the original snapshot hash and label the extraction; hashing an extract alone does not prove it came from the snapshot. Verify unique case IDs, exact mutation ranges/values, success status, required account coverage, input hashes, output hashes/metadata/deltas, and expected branch logs. Do not call a copied status string a new empirical validation.
4. **Native reexecution, when deliberately undertaken:** additionally requires the exact ELF, harness source, Cargo.lock, exact Mollusk commit, local precompile patch, dependencies, and all fixture inputs. The harness currently consumes frozen cases from `output/research/velocity-equality-replay/branch-replay-results.json`; preserve that input or extract case definitions into a separately pinned fixture. The Rust repository path and cached dependencies are not provided by a clean TypeScript install. This scope is not accomplished by steps 1–3.

The review command should write only new reviewer outputs, identify which scope it performed, and fail closed on altered pins, missing/duplicate accounts, contradictory relations, cycles, or inconclusive graph searches. Keep the historical milestone artifacts unchanged.

## One proposed next experiment

Prepare one separately versioned, local **full Anchor-bundle state-diff experiment** using the same deployed ELF and one explicitly constructed, fully documented prestate. Supply all accounts required by Post and TWAP, retain all five instructions for each Anchor role, and execute a producer followed by both equality consumers. Pin Clock to a documented value that permits the intended producer update; retain the original Clock-zero case as a guard control. Record complete before/after bytes and metadata for every supplied account after each instruction and each transaction, rather than only hashes. Require a successful producer oracle write and then measure both Post and TWAP effects on the consumers.

Keep transaction fee handling explicit: first describe the harness's actual fee behavior and all writable signer roles, then evaluate any separate fee-debit model without silently removing instruction-account effects. If a faithful full-transaction fee model is unavailable, label that dimension untested. Native market-account relationships remain preserved; no native opcode interpretation is needed for this experiment. No chain transactions, wallet/private-key operations, or production optimization are part of it.

This experiment is a proposal only. It has not been run in this audit, and even a successful result would establish a bounded fixture result rather than a validator's exact schedule or a throughput gain.
